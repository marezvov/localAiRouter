# AI Gateway: Локально-облачный роутер для автономных агентов

Высокопроизводительный асинхронный HTTP-шлюз (Python 3.12+, FastAPI), совместимый со спецификацией **OpenAI API** (`/v1`). Объединяет локальный инференс (`llama-server` с моделью `Qwen3.6-35B-A3B` на связке **AMD RX Vega 56 + Intel Core i7-4790K**) и произвольные облачные API в единую точку входа.

Оптимизирован для двухуровневых автономных агентов: **«Архитектор / Планировщик»** (облачные модели с рассуждениями) + **«Исполнитель / Кодер»** (локальный Qwen3.6 с горячим KV-кэшем на 262k токенов).

---

## Возможности

1. **Единая точка входа (Single Point of Control):** `http://<IP>:8000/v1` с авторизацией по мастер-ключу `GATEWAY_API_KEY`.
2. **Липкие сессии (Sticky Session Affinity):** Модель намертво фиксируется за `session_id`, исключая хаотичные переключения между шагами задачи агента.
3. **Защита горячего KV-кэша слота (Grace Period):** Учитывая медленный префилл на i7-4790K (~75 т/с), слот удерживается за сессией на 60 сек после окончания генерации. Параллельные запросы чужих задач выталкиваются в облако.
4. **Бесшовный Failover в RAM:** Ошибки `429 Rate Limit` или таймауты перехватываются роутером — запрос пересылается резервной модели прямо из памяти без срыва задачи.
5. **Предобработка изображений:** 4K картинки автоматически сжимаются до 896px JPEG для защиты 4-ядерного CPU i7-4790K от перегрузки.
6. **Мгновенное прерывание (Abort <500 мс):** При нажатии «Stop» в клиенте роутер немедленно сбрасывает вычисления на GPU (`action=erase`).
7. **Встроенный веб-дашборд `/health`:** Темная тема, статус слота 0, скорость t/s, кэш, таблица ключей и кнопки быстрого управления без внешних CDN.
8. **Автономная утилита `checker.py`:** Консольная сводка и глубокий пинг (`--deep`).

## Быстрый старт

### 1. Установка зависимостей
```bash
pip install -r requirements.txt
```

### 2. Настройка секретов (`.env`)
Скопируйте шаблон и укажите ваши ключи:
```bash
cp .env.example .env
```
Заполните мастер-ключ и ключи облачных провайдеров в `.env`:
```ini
GATEWAY_API_KEY=gw-secret-key-12345
GROQ_API_KEYS=gsk_key1,gsk_key2
CEREBRAS_API_KEYS=csk_key1
OPENROUTER_API_KEYS=sk-or-v1-key1
```

### 3. Запуск шлюза
```bash
python main.py
```
Сервер запустится на `http://0.0.0.0:8000`.

## Виртуальные алиасы моделей

В клиентах (Cline, Roo Code, Continue, авто-агент) указывайте `Base URL: http://<IP>:8000/v1`, `API Key: <GATEWAY_API_KEY>` и выбирайте алиас:

* `auto-architect` — облачные модели с глубоким рассуждением (Reasoning) для планирования архитектуры.
* `auto-executor` — локальный Qwen3.6 с вызовом инструментов (`tools`) и облачным фоллбэком.
* `local-only` — строго локальный запуск с очередью до 120 сек.
* `auto-fast` — сверхбыстрые облачные модели (Cerebras / Groq).
* `auto-vision` — мультимодальные модели с авто-сжатием картинок.

## Гибридная классификация и Model-First маршрутизация

1. **Model-First:** В `config.yaml` в алиасах приоритет отдается конкретным моделям (`models: [...]`), а поставщик выбирается по `provider_priority`.
2. **Двойная классификация (Эвристика + LLM):** При обнаружении новых моделей они автоматически прогоняются через быструю LLM (`discovery.llm_classifier`), которая определяет каноническое имя, теги и оценивает окно контекста. Результаты кэшируются в `models_cache.json`.
3. **Режимы выбора моделей (`routing.model_selection_mode`):**
   * `user_first`: сначала модели из конфига, затем эвристическое ранжирование остальных.
   * `user_only`: строго только модели, явно перечисленные пользователем в конфиге.
4. **Канонизация имён:** Поддержка сопоставления GLM (`glm-4-9b`), Llama (`llama-3.3-70b`), Qwen (`qwen-2.5-coder-32b`), DeepSeek (`deepseek-v3`, `deepseek-r1`), Yi (`yi-large`) вне зависимости от синтаксиса провайдера.
